How the switch works

+

Claude Code: the setting it already understands

The switch writes skillOverrides in ~/.claude/settings.json, the per-skill setting Claude Code already supports. Claude Code watches that file, so toggles reach live sessions without a restart. The skill's folder never moves.

+

Cursor and OpenCode: the folder moves, and moves back

Those tools have no off switch, so off means the skill folder is parked in Loadout's Application Support folder. On brings it back byte-identical. Symlinked skills are never moved.

+

The whole kit at once

Select all, or ⌘-click a set, and turn everything on or off in one click. Delete moves folders to the Trash, never rm.

+

Edit CLAUDE.md and AGENTS.md in the same window

~/.claude/CLAUDE.md and ~/.codex/AGENTS.md are read before every session. Loadout shows them next to your skills, with autosave that won't overwrite changes made on disk.

Built to be trusted with your files

Before its first ever write, Loadout backs up settings.json. After that it patches exactly one key and round-trips everything else untouched.

No destructive code path exists: off is a settings entry, shelving moves back, delete goes to the Trash.

MIT-licensed Swift, with all file handling in a separate library covered by its own test suite.

Two network calls exist: a GitHub update check, and PostHog analytics under a random install id. Events carry skill folder names, never file contents. Both are in the source, where you can read them.
